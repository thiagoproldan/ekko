Urgency counts blocking twice: ekko inherits priority and latest finish and still adds 8 for any open dependent, which Taskwarrior advises against under inheritance

Taskwarrior recommends urgency.blocking.coefficient = 0 (and blocked = 0) when urgency.inherit is on, since the blocker already takes what it blocks (taskwarrior.org/docs/urgency; Task::urgency_c takes max(own, inherited) + 0.01). ekko propagates the inputs, the highest priority and the CPM latest finish of the open work waiting, and then adds 8 for waited_on. On this board, 2026-09-21, next with 8 reads 97, 51, 87, 257; with 0, 51, 87, 97, 257 (97 blocks the @icebox chain 31-33). The five @icebox items in the top ten come from the age term, which gives old items up to 2, not from blocking: stashing the icebox fixes that part. The independent replica (target/evals/analise-final/scripts/urgency.py and differential.py) makes any change of coefficient testable. Decide with the user.
