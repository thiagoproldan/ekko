# 844. ekko: one command parses storage.json three times

*Task · done · created 2026-09-27 · [history](../history.md)*

MEASURED 2026-09-27 \~03:30 (-03) with perf 7.2.8 (nix shell nixpkgs#perf, --call-graph dwarf), while fixing 829. `ekko --list pending` on a copy of the ekko board (838 items, 1.4 MB) calls Storage::get, and so parse_map, from display_stats, from list_by_attributes and from blocker_map. That is three full serde reads of the same file for one command. Parsing was the largest part of the profile: memmove, skip_to_escape, has_next_key, Item's visit_map and parse_str came to about 48% of the samples. The command took \~30.5 ms wall with 829's build.

Not measured: how much reading the board once per command would save, and whether the MCP server rereads it the same way on each call. Check both before changing anything: time a single command with one read, and profile a server call.
