State is four independent flags, not one of five states: cancelled then --check is done and cancelled at once, and the board, the stats and --list disagree

## Notes

### <a id="143"></a>143. Measured 2026-09-14 on a scratch board, at 65fff6e. A task's state is stored as isComplete, inProgress, paused and…

Measured 2026-09-14 on a scratch board, at 65fff6e. A task's state is stored as isComplete, inProgress, paused and cancelled: sixteen combinations for five meaningful states, and the commands do not keep an item inside the five. Cancelled then --check leaves isComplete and cancelled both true; the board draws it cancelled and the stats count it cancelled, while --list done lists it as done. Done then --set paused leaves isComplete and paused both true; the command confirms the pause and the task stays done on screen. The cause is structural: Level::of, compute_stats and filter_by_attributes each project the four flags with their own precedence, so three surfaces can give two answers about one item. What the audit points at: a state type with exactly five values, one total transition function covering every command, and every view derived from that state instead of re-deciding it. Small enough to test exhaustively -- five states times roughly ten commands -- rather than by sampling.
