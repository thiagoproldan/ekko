# 827. ekko: the guard ignores EKKO_DIR; a cue on that board never refuses

*Task · done · created 2026-09-26 · [history](../history.md)*

Found 2026-09-26 23:10 (-03) while writing 805's readme, by reading the code; not run. guard.rs state() and boards() resolve the default board with retrieve_ekko_directory(home, home, None, None), so the runtime override EKKO_DIR is not consulted. The index holds the default board (\~/.ekko or ekkoDirectory) and the registered projects. A session started with EKKO_DIR=/x works on /x: it can propose a cue there, and the user can turn it on in the menu, but the hook never indexes it, so it never refuses. The MCP's ask/allow path passes the same home, so refusals and asks agree with each other; only the cues on an EKKO_DIR board are missed. To decide: index the EKKO_DIR board when the hook's environment names it (the hook inherits the session's environment), or refuse a cue proposal on a board the guard does not read. Either needs a test that turns on a cue on an EKKO_DIR board and runs the hook with that variable set.
