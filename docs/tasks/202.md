### <a id="203"></a>203. PROPOSAL 2026-09-21 (session 29cf2249), not yet approved. Everything lives in the ekko plugin plus one new flag in the…

PROPOSAL 2026-09-21 (session 29cf2249), not yet approved. Everything lives in the ekko plugin plus one new flag in the binary.

(1) The SessionStart hook, which already primes, also writes the session's own list at &lt;config dir>/tasks/&lt;session_id>/ from the board. Every hook receives session_id.

(2) A PostToolUse hook on mcp\_\_plugin_ekko_ekko\_\_.\* rewrites the list after each ekko call, so the widget follows every create and set_state.

(3) A FileChanged hook on the board's storage file, registered through watchPaths, keeps the list current when the user changes the board from the terminal or --ui.

(4) The list shows: ✔ tasks done since the session began (the hook keeps the session's first cursor), ◼ work in progress (its text becomes the spinner line), ◻ the next ready tasks, and ekko ids in the subjects.

OUTSIDE EKKO, one setting. A plugin cannot set environment variables (plugins-reference), and Opus 5 needs CLAUDE_CODE_ENABLE_TODO_TOOLS=1. Add CLAUDE_CODE_TODO_REMINDER_MODE=off (read in the binary), so Claude Code stops nudging the agent toward its own list, which would compete with ekko. The gsd-pi project hit exactly that (open-gsd/gsd-pi#2365). showExpandedTodos is already on in .claude-trabalho.

TO VERIFY while building: that a session's own list redraws when it is written from outside (the test used a shared list via CLAUDE_CODE_TASK_LIST_ID); that the switch works through settings env; how ekko's files coexist with tasks the agent creates through TaskCreate (ids, .highwatermark, .lock).
