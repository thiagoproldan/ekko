# 280. Temp-file cleanup can delete a live writer's file: remove only the temp files whose writer is dead

*Task · done · created 2026-09-21 · [history](../history.md)*

Storage::new runs clean_temp_dir on every open and removes any file in .ekko/.temp older than 1 s (TEMP_FILE_ABANDONED). A write whose fsync stalls past a second, which btrfs does under load, loses its temp file to the next ekko process that opens the board: the tasklist hooks, and every --resources server, which opens the board every 2 s. The rename then fails with ENOENT, and in the current order counters.json was already written. The temp name already carries the writer's pid (temp_file_path): remove a file only when /proc/&lt;pid> is gone, Linux-only as the crate already is, whatever its age.
