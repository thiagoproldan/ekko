### <a id="601"></a>601. BUILT in 1970e56 (signed) on branch menu-settle, worktree ekko-menu in session 5cf94fb7's scratchpad; not pushed, not…

BUILT in 1970e56 (signed) on branch menu-settle, worktree ekko-menu in session 5cf94fb7's scratchpad; not pushed, not released. Why the old guard failed, measured in a Konsole window opened as the menu opens one: the command starts \~650 ms after launch and the window takes the focus \~30 ms later, so 250 ms after the first draw, then tcflush, ended before a person typing elsewhere notices the window. The fix (menu::Settle): a key counts once the menu has been up, or back in focus, for SETTLE = 1 s, and the keyboard has been quiet for QUIET = 0.4 s after any key dropped, so typing that runs on is dropped whole; focus comes from xterm's mode 1004 (Konsole sends ESC [ I), on while the menu runs and off at its end. Space only marks now: it no longer chooses in a single-choice question. Asks stay non-blocking (decision [590](../decisions.md#590)). Checked: cargo test (322 unit + 36 integration), clippy -D warnings, and end to end in a real Konsole window on a scratch board, keys sent through Konsole's D-Bus: v0.20.0 recorded 'Primeira' from a space at 0.4 s (the accident, reproduced); this build dropped a space, '1', Enter and 'x' sent within the first second and recorded the '2' sent at 2 s; a lone '2' at 1.1 s counted. Left: push and release at the user's word (procedure 234).

RELEASED as v0.20.1 (release commit dd2def7, signed tag, CI green; every step of scripts/release.sh passed in \~5 min: 358 tests, semantics 27 of 27, the largest prime 5,795), and the system switched to it (ekko --version 0.20.1). A session's menu is launched from its own MCP server's binary, so the fix reaches each session only after it restarts.
