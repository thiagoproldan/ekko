# 803. ctx: refuse a git or rm command that would destroy work with no other copy

*Task · done · created 2026-09-26 · [history](../history.md)*

Decision [801](../decisions.md#801) (task [770](770.md)). A PreToolUse hook on Bash in ctx, beside check-bash-read. It parses the command into calls with the pgrep guard's lexer (\~/NixOS/scripts/claude-code-pgrep-guard.py; generalized in /tmp/770-replay/replay.py). It follows cd and git -C, reads the repository's state, and refuses only when something would be lost, naming it:

- reset --hard, checkout -f, switch --discard-changes: tracked changes (git status --porcelain -uno);
- checkout [&lt;rev>] -- &lt;paths>, checkout ., restore without --staged, rm -f: changes under those paths;
- clean -f: what git clean -n with the same flags lists;
- stash drop and stash clear: a stash whose changes are not already in the work tree (git stash show -p | git apply -R --check);
- branch -D: commits reachable from no other branch and no remote;
- worktree remove --force: that work tree's changes, untracked files included;
- a forced push whose destination is the remote's default branch, when the remote tip is not an ancestor of what is pushed;
- rm -r of a folder inside a repository: untracked or modified files under it; of a whole repository: its changes, stashes, and branches with no remote.

The reason says what would be lost and how to keep it: commit, or git stash push -u, then run it again.

Not guarded: rm -r outside any repository, since no state there says whether a copy exists (Claude Code itself still prompts before removing a critical path), and a script the model writes and then runs.

Tests: each rule gets a case that refuses and one that passes. Log every call it examines and every refusal to ctx's ledger, to be counted after a week: the replay (note 797) cannot recreate the state those 93 calls met.
