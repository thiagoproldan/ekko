THE PROBE, evals/docs/topics.py (uncommitted): the board's own links make 2,036 edges among 904 items, and only 49 items have none. Weighted label propagation over them, with no model, gives 49 topics of 5+ items (largest 39, 29, 26, 26, 24). They read as topics: commit trailers and long-term memory (337, 396), questions through ask (395), confining sessions to boards and project links (697, 811), ctx's cold returns (540, 809), auto mode for the reset (747), the guards (770, 803, 804), the session floor (431), the cue guard (805), the board inside its own folder (503), waits and wakes (389). Noise: the release tasks group together through the release procedure.

RAG: it retrieves pieces to answer a question; docs need everything covered once. Embeddings and ranked search are ruled out for ekko (note 173), and questions are already served by search and context.

GRAPHIFY: the same shape (a graph, communities, and --wiki writes one article per community), but on prose it extracts the graph with a model: its SKILL.md says code goes through AST for free while docs need semantic extraction, which costs tokens, and decision [162](../decisions.md#162) found it did not apply to prose. Here the graph is already explicit. Microsoft's LazyGraphRAG made the same move, building the graph with no model: its indexing costs 0.1% of GraphRAG's (microsoft.com/en-us/research/blog/lazygraphrag-setting-a-new-standard-for-quality-and-cost/).

GRAFF: a code map with no code yet; decision [966](../decisions.md#966) keeps ekko, ctx and graff apart. The input here is the board, whose model only ekko knows. Later, graff could link a decision to the code its commits touched, on its own side.

DIRECTION, pending the rest of the research and the user's word: ekko docs in ekko, written by code with no model in it (note 173: no LLM in ekko), at 0 tokens. Rules pick what is current (no stash, nothing superseded, no questions; handoffs are transient), the links group it into topics, and the cited ids become links between pages. Prose, if wanted, comes from the agent in a session, one topic at a time (the largest is 39 items, never the whole board); the user's memory page can be the overview.

STILL TO RESEARCH: file layout and formats (ADR tools such as MADR and log4brains, changelog generators, Backlog.md, beads, Diátaxis).

### <a id="996"></a>996. RESEARCH 2, 2026-09-30 \~23:55: how others lay out docs like these, and what ekko's board would fill.

- Decisions: ADRs are one file per decision. MADR keeps them in docs/decisions/NNNN-title.md, with status in front matter, 'superseded by ADR-0123' among the statuses (adr.github.io/madr). log4brains publishes such a folder as a static site with no model, names files by date to avoid merge clashes, and treats an ADR as immutable except its status (github.com/thomvaill/log4brains).
- Diátaxis splits docs by the reader's need: tutorials, how-to guides, reference, explanation (diataxis.fr). Here procedures are how-to guides, decisions are explanation, gotchas are troubleshooting, and the task record is reference.
- Keep a Changelog: written for humans, latest first, grouped, never a dump of the git log (keepachangelog.com/en/1.1.0).
- Backlog.md keeps tasks, docs and decisions as separate files in backlog/, written by hand, not generated; 'backlog board export' writes a markdown report of the board (github.com/MrLesk/Backlog.md).
- ai-memory consolidates sessions into a git-backed markdown wiki, deterministically by default, with a model only as an opt-in (github.com/akitaonrails/ai-memory). beads summarises old closed tasks with a model, as 'memory decay' (github.com/steveyegge/beads), which note 173 ruled out for ekko.
- GitHub: a link to #x reaches an &lt;a id="x">&lt;/a> in the same file, through the user-content- prefix its script resolves.

SIZES on ekko's board, live items (characters): decisions 77 (85.5k, 2 superseded), gotchas [80](80.md) (59.4k, 6 superseded), procedures [25](25.md) (32.7k), handoffs 42 (87.7k), plain notes [335](312.md#335) (501.9k; 38 superseded, likely earlier handoffs), questions 135 (96.9k, all answered), tasks [211](207.md#211) (142.7k). From 2026-08-24 to 2026-09-30.

SO: a page per kind holds the knowledge well (decisions, gotchas, procedures: 33-86k each). The record of the tasks does not fit one page: with their notes, handoffs and answers it is about 830k characters, so it splits, one page per task under an index.

SAFETY, whatever the layout: write only files that carry ekko's 'generated' mark, and refuse to overwrite one without it, since a project's docs/ may hold pages written by hand.

Explanation: O repositório do ekko é público, e o board não está nele (.ekko/ fica fora do git).
