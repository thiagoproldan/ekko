Keep what Claude Code sends ahead of the conversation stable: a test pins a hash of the server instructions and the always-loaded tool definitions

Any byte change there makes every session resumed after the upgrade write its whole context again: six such rewrites on 2026-09-21 cost 5.34M units, 9.6% of the handoff era (evals/claude-code/transcripts.py; note [258](180.md#258)). A test that fails when the instructions or the five always-loaded definitions change, until a constant is bumped on purpose, makes each change a decision to batch into a release that changes them anyway. Measured today: the always-loaded definitions are 5,658 characters, \~2,400 tokens (the comment above ALWAYS_LOADED in src/mcp.rs says about 1,500); the instructions are 1,984 of the 2,048 characters Claude Code keeps (note [167](../notes.md#167)), so one more sentence cuts the last rule off. Always-loading, by per-session use since 2026-09-15 (37 sessions, 93 calls on average; context 0.41, create 0.38, search 0.30, set_state 0.27, edit 0.19): \~0.1 x 2,400 x 93 = 22k units per session, against 9k to 19k for loading on demand through ToolSearch, and it saves \~2.9 s in about half the sessions. Keep it, and do not churn it.
