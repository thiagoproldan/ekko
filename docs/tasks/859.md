# 859. ekko: an MCP write parses the board it just wrote

*Task · done · created 2026-09-27 · [history](../history.md)*

MEASURED 2026-09-27 while doing 844, on a copy of the ekko board (1,325 items, 1.75 MB), with strace -k on a warm `ekko --mcp`: every write call (create, set_state) reads storage.json whole once, after writing it, and nothing else does: reads after the first come from get_shared's cache. The stack is mcp::Server::tool_result -> wake::untold -> Storage::get_shared -> parse_map: the version the write produced is not kept, so the first read of it parses.

Idea, not tried: keep the map a write saved as that version. fstat the temp file before the rename (the inode, mtime and length carry over), and keep_board after a successful rename, so another process's later write is still a new inode and misses. It needs a copy of the map (about a quarter of a parse by 0b8a299's fit) and holds only if what a parse of the file gives equals the map written, which the round-trip tests suggest but no test states.

Not measured: the parse's share of a write call (single calls took 32-38 ms). Measure a write call with and without, back to back, before choosing.
