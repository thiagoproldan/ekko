## Notes

### <a id="177"></a>177. WHAT THE PLAN SAYS: the MCP spec lets a tool declare an outputSchema and answer with structuredContent beside its text…

WHAT THE PLAN SAYS: the MCP spec lets a tool declare an outputSchema and answer with structuredContent beside its text content, but Claude Code's docs do not say how that reaches the model. The idea is to carry the cursor and ids as structure in the replies of prime, changes, next and the writes, keeping today's text as the main channel. Acceptance: a documented test of what the model receives with and without structuredContent. Depends on 3.1, which is done (the rev cursor).

HOW. Reuse the probe server from the 4.1 task's note (rebuilt from transcript 7f421024). Add one tool whose text says only 'see the structure' while its structuredContent carries a unique marker, and a second variant that also declares an outputSchema. Run claude -p --strict-mcp-config --mcp-config &lt;probe.json> --allowedTools &lt;that tool> 'call the tool and quote every marker you received', once per variant: the two short messages the user was told about (for scale, the handoff probe on 2026-09-21 cost about US$0.23 of quota). Read probe.log and the answers: a quoted marker means structuredContent reaches the model -- note whether as JSON, instead of the text, or beside it.

THEN. If it arrives beside the text, decide with the user whether the cursor and ids move there to shorten the text replies. If it replaces the text or never arrives, cancel this task with the evidence. Either way, record the result as a note here, with the Claude Code version (claude --version).

Approved 2026-09-21: the probe server lives in the repo as evals/claude-code/, in the mold of evals/agent/.

### <a id="225"></a>225. To see what Claude Code sends the model without spending quota, run claude -p against a stand-in for the Anthropic API…

To see what Claude Code sends the model without spending quota, run claude -p against a stand-in for the Anthropic API, as evals/claude-code/structured_content.py does: nix develop -c python3 evals/claude-code/structured_content.py. The setup: ANTHROPIC_BASE_URL points at a local HTTP server that answers POST /v1/messages (as SSE when the body asks for stream), ANTHROPIC_API_KEY is a dummy, and CLAUDE_CONFIG_DIR is a throwaway dir. Every CLAUDE\* and ANTHROPIC\_\* variable of the calling session is dropped, so the login and the settings stay out. The stand-in plays the model: it answers the first request with tool_use blocks, and the next request carries the tool_result blocks exactly as a model would get them. Evidence lands in target/evals/claude-code/. Traps in 2.1.278: tool search is off for a base URL that is not a first-party Anthropic host, so MCP tools arrive in full in tools. Each request ends with a message of role system, so look for tool results in the whole conversation, not in the last message. Point CLAUDE_BIN at the binary behind the Nix wrapper, since the wrapper adds --settings and ekko's --mcp-config. It shows what the client sends, not how a model reacts: a mention still needs an interactive session, and how a model reads a reply still needs a real run.
