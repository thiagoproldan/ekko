- The ledger ($CTX_STATE/handoff.jsonl, 2026-09-23..26) logged 19 handoff asks, 4 of them with the window at 87-98%.

What is new:

1. The model is told the reading: at session start, on each prompt the user sends (one line, say '5h 62%, resets 21:40, cap 85%'), and when it crosses a band. It can then pace its work, for instance not start a paired run at 70%.
2. Past the cap, the session starts no new work: no subagents and no headless claude runs (PreToolUse), no /clear and 'continuando' from auto-reset, no scheduled prompt. It writes its handoff and stops, instead of the reset it is asked for today.
3. The reserve, 15%, is the user's: a prompt the user types still goes through, with the reading on it. It is for emergencies, or whatever else the user spends it on.

To settle: whether past the cap is a refusal or a warning (decision [801](../decisions.md#801)'s pattern for guards: refuse with the reason, and the user's answer through ekko's ask lets that call through once); one variable for the cap and the handoff ask, or two; whether the week (seven_day, also in the status line's input) gets a cap too; and how to tell a scheduled prompt from the user's, since a hook's input does not say who sent it (the Stop hook's .scheduled mark in $CTX_STATE/cold/ is the only lead).
