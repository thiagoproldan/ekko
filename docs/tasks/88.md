BUILT 2026-09-21, committed as 5f10139 on main (local, not pushed, not released), as decision [232](../decisions.md#232) says. State::Waiting is the sixth state, stored as waiting: true only when set, and it resolves after paused in State::of. State::can_start is is_open minus waiting. It is used by Reader::ready, and therefore by next, prime's ready list, freed_by_cancelling and changes.released. It is also used by --list ready and by readiness_changes, so a write never names a waiting task in nowReady or nowBlocked. --list overdue and pending still include it (is_open). Prime has a 'Waiting (N)' section after Blocked: WAITING_KEPT 5, ordered by priority then id, '+N more: search with the waiting filter'. That line's MORE_LINE is reserved only when the section exists. Blocked leaves waiting tasks out. Stats has a waiting field, counted in the total. The stats line shows 'N waiting' in cyan only above zero. Board view icon ◔ (U+25D4, cyan). --ui: nf-cod-watch U+EB7B, or ◔ in plain glyphs, ORANGE, plus a 'waiting' chip. CLI: --set waiting and --list waiting. MCP: set_state enum and the search filters list, with the instructions unchanged. The Set outcome prints 'Waiting task: N'. CHECKS: cargo test 339 green, with new tests in item, ekko, agent, render, tui/draw and tests/mcp.rs. Clippy -D warnings clean. semantics.py 27 of 27 and scale.py prime_chars unchanged (5735/5829/5856/3573), both on a fresh release build: target/release had been stale at 0.10.1, so rebuild it before the evals. On a copy of this board, a board without waiting gives a byte-identical prime and board view, and --set @180 @220 waiting moves both out of Ready and next into the Waiting section. KNOWN: context's 'Roots, free to start' can list a waiting root, marked [waiting]. DO NOT set waiting on the real board before v0.11.0 is installed and Claude Code restarted: 0.10.2 drops unknown fields on its next write (gotcha [194](../gotchas.md#194)), and the task silently becomes pending again.
