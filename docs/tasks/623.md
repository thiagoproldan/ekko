## Notes

### <a id="655"></a>655. CAUSE AND FIX, 2026-09-25: no race between commit and log, but a real bug. commits::naming passed --since=&lt;UTC date of…

CAUSE AND FIX, 2026-09-25: no race between commit and log, but a real bug. commits::naming passed --since=&lt;UTC date of a day before the item>, and git reads a bare date as that day at the current time of day, in the local zone. Whenever the local date is behind UTC's (21:00-24:00 in Brasília), the bound fell at the present moment and dropped every earlier commit; the test passed anyway unless a second turned between its commit and its read, as under load at 23:45. Shown with git itself: TZ=Pacific/Pago_Pago git log --since=2026-09-24 listed none of that day's commits. Fixed in c72e07b on branch flaky (worktree \~/Projetos/ekko-copies): --since=@&lt;seconds>, a day before the item. Suite, clippy and the MCP tests under TZ=Pacific/Pago_Pago pass. Not landed: pushing and a v0.22.1 are the user's call.
