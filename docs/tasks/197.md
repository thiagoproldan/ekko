### <a id="198"></a>198. RESEARCH 2026-09-21 (session 29cf2249), asked for by the user, who chose the status line after it. They want the native…

RESEARCH 2026-09-21 (session 29cf2249), asked for by the user, who chose the status line after it. They want the native task-list view (✔ ◼ ◻ under the spinner) for ekko.

VALIDATED in code.claude.com/docs/en/statusline, settings and plugins-reference:

- The status line runs locally and consumes no API tokens.
- It renders in its own row at the bottom, above the footer badges, and nothing moves it next to the spinner.
- It re-runs on each new assistant message, after /compact and on permission-mode changes, debounced at 300 ms, and also every refreshInterval seconds (minimum 1; the user's is 30).
- It can print several lines. It hides during autocomplete, the help menu and permission prompts.
- A slow script freezes it, and the next update cancels the script.
- A plugin cannot ship statusLine; its settings.json takes only agent and subagentStatusLine. The user's statusLine comes from the --settings file NixOS generates, which runs shunt-statusline, so this needs a wrapper there that runs both.

SHAPE PROPOSED, not yet approved. ekko --statusline reads the status-line JSON on stdin and finds the project from its cwd. It prints 2-4 lines: a counts line, then ◼ for work in progress and ◻ for the next ready tasks, clipped to the width. It must stay fast; prime takes 0.3-34 ms on the scale boards.

RULED OUT: feeding Claude Code's native task list; see the gotcha written with this note. PLAN B for text next to the spinner, not tested: spinnerVerbs or spinnerTipsOverride in the project's .claude/settings.local.json, which Claude Code reloads live. It shows one line, only while Claude works, and ekko would be editing a Claude Code config file that also holds permissions.
