# 274. A server older than the board should refuse to write and say to restart Claude Code: a version fence in counters.json

*Task · done · medium priority · created 2026-09-21 · [history](../history.md)*

Gotcha [194](../gotchas.md#194) is a recurring cost: after each release, sessions started before it keep an old server. On 2026-09-21 the search filter decision was refused as UNKNOWN_LIST_TERM four times between 02:44 and 02:50, minutes after v0.8.0 (02:32) introduced it, by servers started before the rebuild; and at 10:30 a 0.10.2 --resources server was still running (pid 439989, fork 8a700fad). Since 0.11.0 an older write keeps the fields it does not know (task [246](246.md)), but an older server still answers by older rules. Design: every write records the writer's version in counters.json (say minWriter), which 0.11 and later keep as an unknown field; a server whose version is lower refuses writes with 'this server runs X and the board was written by Y: restart Claude Code', and its reads say so in one line. It has to ship one release before the first one it protects.

## Notes

### <a id="296"></a>296. Checked 2026-09-21 against the system generations (/nix/var/nix/profiles/system-315 to 328): of 10 changes of the…

Checked 2026-09-21 against the system generations (/nix/var/nix/profiles/system-315 to 328): of 10 changes of the installed ekko, 9 came with a new version and 1 was a rebuild at the same version (0.7.1, generations 317 to 318). So a version fence would have caught about 9 in 10; its real limit is the release it has to ship ahead, as this task says. A complement with no change to storage, though with the same lag, since any check has to be in the server that goes stale: the plugin starts `ekko` from PATH, so a server can record at start what `ekko` resolves to (path and inode) and compare it on each call; a nix switch changes the store path, a cargo build the inode. Refusing writes on either signal would also block the session that made the release, whose handoff comes after the rebuild; a one-line warning is the gentler choice. Not built on purpose: warn or refuse, fence or binary check, is the user's call.
