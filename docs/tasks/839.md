# 839. Two guards refusing one Bash call: the model reads only one of the reasons

*Task · done · created 2026-09-27 · [history](../history.md)*

MEASURED 2026-09-27 02:55-02:56 (-03), session 8e199d1a (Claude Code 2.1.283), live check of 805. Gotcha 833's cue and ctx's work-loss guard both refused `cd ~/.local/state/ctx-805-live/repo && git reset --hard`. ekko's record bv762s holds both reasons. On both tries, though, the tool error the model read carried only ctx's reason, so the gotcha's text never reached the model. With the tree clean, ctx passed and ekko's refusal came through whole.

hooks.md (read raw) gives the precedence, deny > defer > ask > allow, and says matching hooks run in parallel. It does not say which reason is shown when two hooks deny. Which one Claude Code picks (config order, the last to finish?) is not measured: 2 tries are not a loop.

The mechanism that matters: the model follows the reason it reads. A gotcha that says "back up first" is lost whenever ctx also refuses the call. The user still sees both reasons, since ask with allow quotes the record.

A possible direction, not settled: `ekko --guard --refuse`, which ctx already calls on its refusal path, appends the gotcha texts of the cues that hit the same call. The model then reads both reasons whichever one Claude Code shows. The reverse case, where Claude Code shows ekko's reason and drops ctx's, needs its own answer.
