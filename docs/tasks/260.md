# 260. Require a short title on every task

*Task · done · created 2026-09-21 · [history](../history.md)*

Evaluate the premise before building anything: is a required title worth it? The first line of the description would be the title, at most \~100 characters, and the rest the body. The views (board, prime, next, the Claude Code task list) show only the title; context shows everything. No new field: the storage format is unchanged. Proposed by the user on 2026-09-21, asking whether it helps or is just a task with a note attached -- it is not, since the body is the task's what and a note is its why and history. TO MEASURE FIRST: on this board, how many tasks have a first line over 100 characters today; how much smaller the prime, next and context get with title-only lines (scale.py and the real board, against the 5,867-character prime of 2026-09-21); whether an agent picks work equally well from titles alone (semantics.py); the cost of the rule (create refusing a long first line, the items that already exist, the CLI getting a body only through - or --edit). Decide with the user from the numbers, and alongside 180's measurement, since both are about the fixed context cost
