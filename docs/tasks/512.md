Ekko now records who wrote each item and links a task to the commits that carry it, and a server started by a Nix store path says when an upgrade has replaced it.

\## Who wrote each item

Every item created from now on records who wrote it: the Claude Code session -- its profile, its terminal and the conversation it ran then -- or you, at the terminal. `context` and `--context` say it on a line of its own, `written by trabalho on pts/5 · a6b026e6` or `written by the user`, and a `by:NAME` filter in `--list` and `search` finds what one author wrote: `by:user`, a profile such as `by:trabalho`, or the start of a conversation. It is set once and kept by every later write, a restore included. Items written before this release name no author.

\## Commits linked to tasks

A commit names the tasks it carries with a trailer at the end of its message, `Ekko: 469`, or `Ekko: 125, 396` for several; a uid does as well as an id. `context` lists the commits naming an item, read from the git history of the project's folder on each read and never stored, so a rebase, a cherry-pick or a squash that keeps the message keeps the link. Those on the branch checked out come first, and the rest are marked `(not on main)`. A line naming anything but ids and uids is no trailer. A session that puts a task in progress on a project in a git repository is told the trailer in a notice; nothing is installed in the repository.

\## The replaced-binary note under Nix

Since v0.12.0 every reply of a server whose binary an upgrade replaced ends with a note asking the user to restart Claude Code. It never fired under the Nix-built plugin, whose command is pinned to a store path that a switch never changes. A server started by a path now also watches its bare name on `PATH`, when that led to the same binary at start, and resource reads carry the note too, so the resources server says it as well. It guards the upgrades after this one: a server running v0.18.0 stays silent through the rebuild that brings v0.19.0.

Items store one new field, `createdBy`, which an older Ekko keeps as it is. The `search` definition gained `by:NAME`, so what Claude Code sends ahead of the conversation changes, and a session resumed after the upgrade writes its context once. After upgrading, restart every Claude Code session.
