### <a id="446"></a>446. BUILT in 55e506b, on main and pushed (session 81ba8737, 2026-09-23), not released. The record is not a new storage…

BUILT in 55e506b, on main and pushed (session 81ba8737, 2026-09-23), not released. The record is not a new storage field: the new handoff sets supersedes, the field decisions already use, to the handoff it demotes. Why: an MCP server still on an older binary rewrites a note keeping only the fields it knows (gotcha [194](../gotchas.md#194)), and it knows supersedes, so nothing is lost while sessions upgrade; and the derived superseded_by, with its trash rule, comes for free. context lists a replaced handoff as '[handoff, replaced by N]', clipped even under detail full; its own id prints it whole, as 'note, a handoff a later one replaced', under 'Replaced by, a later handoff'; search and links mark it too. A note without a kind now supersedes only as a handoff, so a replaced one takes no kind, and a handoff moved to another task lets go of the one it replaced. OPEN QUESTION SETTLED: no backfill. The handoffs replaced before this (401 and 409 on 337, among others) carry no record and read as before; a backfill would need a heuristic on the text 'WHERE IT STOPPED' and a way to set supersedes on plain notes that nothing else should have.
