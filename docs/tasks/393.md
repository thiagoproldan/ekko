# 393. Flaky test directories: tests that run in parallel in one process can be handed the same temp directory, and the first…

*Task · done · medium priority · created 2026-09-22 · [history](../history.md)*

Flaky test directories: tests that run in parallel in one process can be handed the same temp directory, and the first to finish deletes it under the other. Seen 2026-09-22 in CI on b875399 (run 35802269661, attempt 1): storage::tests::an_unreaped_zombie_holder_does_not_keep_the_lock panicked at src/storage.rs:951, NotFound opening dir/.lock with create, so dir itself was gone; the re-run passed, as every local run did. temp_ekko_dir names it ekko-test-&lt;pid>-&lt;nanos>. Likely cause: GitHub's runners are Hyper-V VMs whose clock can advance in 100 ns steps, so two tests starting in the same step collide. The same name with no counter is in src/config.rs, src/directory.rs, src/holder.rs, src/mcp.rs, tests/cli.rs, tests/concurrency.rs and tests/mcp.rs (ops, tasklist and project add a per-test tag). Fix: a process-wide AtomicU64 in each name, or one shared helper. DONE 2026-09-22 \~21:40 as e1248b0 on main, pushed, CI green on the first run: paths::test_dir(prefix) names each unit test's directory with the process, the clock and a process-wide counter, and the eleven helpers in src/ call it; tests/cli.rs, concurrency.rs and mcp.rs each count their own. New test: test_dirs_asked_for_at_once_are_all_different (8 threads x 200 names, all distinct). 312 tests and clippy clean. Ships with the next release.
