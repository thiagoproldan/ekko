# 640. History keeps no daily versions: it counts days back from now

*Task · done · created 2026-09-25 · [history](../history.md)*

storage.rs's stale_versions keeps the 50 newest versions of storage.json, then should keep the newest of each day for 14 days, but it buckets a version by its age from now, (now - version) / DAY. While a version is under 24 hours old, any newer version past the newest 50 shares its bucket and deletes it, so under daily use nothing past the newest 50 ever reaches a day of its own. Seen 2026-09-25: ekko's history/, kept since v0.13.0 (2026-09-22), holds 51 versions, all from the last 6 hours. The fix buckets by calendar day. history_keeps_recent_versions_and_one_a_day passes either way, since it prunes one static list: the new test prunes across successive writes over several days. Found while designing 503.
