*Task · done · high priority · created 2026-09-21 · [history](../history.md)*

Tell the user when to hand off, and hold the turn for the handoff: built in ctx (github.com/thiagoproldan/ctx), the fork of shunt that works with ekko, not in ekko -- a status line with the session's context against the \~160k optimum and the task it holds, and a Stop hook, at zero token cost

WHY. Handing off is the largest lever left (decisions [161](../decisions.md#161)-164, note [258](180.md#258)), and it happens late: the five clears of 2026-09-21 came at 199k, 349k, 356k, 506k and 719k of context (median 356k, 34 to 333 calls into a session), each triggered by the user by eye.

THE MATH, per call in units of one uncached input token (Opus 5: output 5x, 1 h cache write 2x, read 0.1x), algebra checked: for segments of L calls on a base B = b + R with reset overhead W, c(L) = 2d + 5o + 0.1B + 0.05dL + W/L. Minimum at L\* = sqrt(20W/d), where the context is C\* = B + sqrt(20Wd) and c\* = 2d + 5o + 0.1B + 2 sqrt(0.05dW). Handoff era of 2026-09-21: d 2.1k, o 1,044, b 37.9k, R \~30k, W \~210k (median orientation 163k plus writing the handoff), so L\* \~45 calls, C\* \~162k, c\* \~25.6k per call, against \~32.1k at the median clear point (137 calls, 356k): -20%, and -48% for the 719k segment. Sensitivity: W from 100k to 400k and d from 1.4k to 3.2k put C\* between 121k and 228k. Each turn a reset loses adds \~25k to W: with 10, C\* moves to \~207k and the gain at the median falls to \~-11%, which is what 259's paired test decides.

WHAT. ekko --statusline reads Claude Code's status line JSON on stdin (context_window.total_input_tokens, rate_limits.five_hour.used_percentage, session_id; code.claude.com/docs/en/statusline) and prints e.g. 'ctx 212k, hand off now, 263 in progress'. A status line runs locally and costs no API tokens: it informs the user without adding anything to the context. Thresholds configurable (default amber at 160k, red at 230k), the five-hour window above \~85% as a second trigger (note 164), and with owners (264) the task this session holds.

ACCEPTANCE. Wired in the four profiles through the NixOS module; renders in under 10 ms; says nothing about a board when the folder has none.

### <a id="411"></a>411. BUILT, uncommitted, session 06637eec, 2026-09-23. \~/Projetos/ctx (cloned from github.com/thiagoproldan/ctx, which was…

BUILT, uncommitted, session 06637eec, 2026-09-23. \~/Projetos/ctx (cloned from github.com/thiagoproldan/ctx, which was empty) holds shunt 2.0.0 imported verbatim from \~/NixOS/pkgs/shunt (staged in the index as the baseline, so git diff shows only ctx's changes), renamed to ctx (SHUNT\_ to CTX\_, shunt- to ctx-, state in \~/.local/state/ctx), and packaged as a flake at 0.1.0 (flake.nix, package.nix; nixpkgs locked to NixOS's 6774f7bc; antigravity-cli allowed as unfree). NEW: src/hooks/handoff, a Stop hook. Past CTX_HANDOFF_TOKENS (default 250k, from note [407](337.md#407)), or with the 5-hour window past CTX_HANDOFF_5H (85), it keeps the turn open once through hookSpecificOutput.additionalContext, shown as 'Stop hook feedback' (the string is in Claude Code 2.1.280's binary), asking for the ekko handoff and a /clear. It asks once per band (T, 2T, ...), and a compaction re-arms it. It stays quiet while stop_hook_active is set or while background tasks or crons are pending. The context comes from the transcript's last main-thread usage; the 5-hour reading comes from the status line, which now leaves it in $CTX_STATE/sessions/&lt;sid> (trusted for 10 minutes). Each ask is logged to $CTX_STATE/handoff.jsonl. The status line threshold moved from 200k to 250k, and 0 turns a flag off. nix build runs the suite: 136 ok. NOT DONE: commits and push (the user's word), the NixOS wiring (flake input, module switched from pkgs.shunt, mv \~/.local/state/shunt \~/.local/state/ctx), and a live check in a real session.
