### <a id="508"></a>508. ANALYSIS, 2026-09-24, session 844752fe, at the user's question ('e se olharmos para as bases novamente e tentar aplicar…

ANALYSIS, 2026-09-24, session 844752fe, at the user's question ('e se olharmos para as bases novamente e tentar aplicar o Attention is all you need no ekko de alguma forma, daria?'). Today ekko works like an RNN: the handoff is the hidden state each session compresses into (3,500 characters) and the next one reads, with an RNN's faults (fixed size, the old fades, it rests on the last step writing well: note 500); the prime is attention with fixed weights, the same 6,000 characters in the same order (text_within in src/agent.rs) whatever the session is about to do. Note [497](337.md#497) names the bottleneck: 275 notes, one fixed prime. The transformer's move is to keep everything addressable and pull by relevance to the current query, softmax(QK^T)V: Q the user's prompt (UserPromptSubmit) or the command about to run (PreToolUse); K the item's text, or a gotcha's literal cue; V the item, clipped; QK^T the BM25 already in src/lexical.rs, which today runs only when the model calls search; top-k a sparse attention; multi-head the lexical, graph (the blockers and notes of the task in focus), recency and salience signals (note [340](337.md#340) (7)); position the prime's 'N writes ago', a recency decay an ALiBi; the KV cache the prompt cache (inject at the end, never touch the prefix). It is RAG or memory networks, nothing new; the frame names what is missing: the query. Evidence already here: in note [402](337.md#402) the pkill -f lesson loaded at session start caught 0 of 3, and a check on the command before it runs catches all 35. On tokens: ekko's part of the floor is 5.1k (the prime 2.6k), re-read at 0.1, \~1% of usage; the cost is re-reading long context (above 160k, \~35% of the bill, note [402](337.md#402)). The link: segmentation's net falls from \~20% to 11% if each reset loses ten turns (notes [402](337.md#402), [267](267.md)), and a session spends \~30k before its first productive action (note [294](259.md#294)); the right notes arriving with the first prompt shrink both. Where the analogy breaks: (a) language: W_Q and W_K put query and key in one space, but the user writes Portuguese and the board is English, so BM25 matches only what both share and concepts would need multilingual embeddings; (b) top-k zeroes what soft attention only weakens: a gotcha missed is a mistake repeated, so destructive traps stay on the deterministic cue (402); (c) context only grows: each injected token costs 2 once and 0.1 per later call (note [340](337.md#340)), so a cap and no reinjection; (d) relevant is not true: a stale note retrieved misleads (184), so supersedes and the stash stay.

TOOL RESULTS' TAIL: the top 10% of results hold 60% of their cost; a cap at 2,000 tokens would drop 1.7% of the bill. QUALITY PROXY (the user's corrections, a strict pattern, \~75% precise by eye): 2.9% of prompts under 100k of context, 4.2-7.9% above with no trend; within sessions of 8+ prompts the second half is no worse (4.8% against 5.1%): no evidence here that a long context degrades the work. SO: retrieval by the prompt is refuted (note 517); the lens explains instead where the bill goes and why segmentation pays (notes [402](337.md#402), [407](337.md#407)): most of what a long session re-reads is its own past output and thinking, which a handoff distills.
