## Notes

### <a id="145"></a>145. Measured 2026-09-14. One done task and one cancelled task on a board print [1/2] in the title and 100% on the line…

Measured 2026-09-14. One done task and one cancelled task on a board print [1/2] in the title and 100% on the line below it. On the real boards, --projects shows winwayland as [46/54], which is 85%, while inside the project the percentage is 88%; minium shows [76/83], 91%, against 96% inside. In the code, render.rs item_stats and directory.rs count_items count every task, while compute_stats and the roadmap subtract the cancelled ones. Which definition is right is a decision rather than a bug hunt -- the percentage's reasoning, that cancelled work is not work so a board that drops something can still reach 100%, was argued and kept -- but one definition has to hold everywhere a total is shown.
