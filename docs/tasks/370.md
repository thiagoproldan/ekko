# 370. Each session's own view of the board, and who did what: every Claude Code session in one project shows the same board…

*Task · done · high priority · created 2026-09-22 · [history](../history.md)*

Each session's own view of the board, and who did what: every Claude Code session in one project shows the same board, so a session's prime, next and task list do not tell the user which tasks are that session's.

THE USER, 2026-09-22, who marked it important: 'cada session dentro daquele mesmo projeto mostra o mesmo board, precisamos de alguma forma mostrar as tasks da session corrente, ou melhorar a visão do usuário nisso, e tbm utilizar o id da session como assinatura de concluinte de task e ao mesmo tempo dar nome aos bois de quem é cada task, mas o lado ruim é que iremos tratar sessoes de forma efemera a cada quantia de tokens de contexto, então precisamos ver melhor isso'.

THREE ASKS. (1) Show the current session's tasks, or otherwise make it clearer to the user which tasks each session has. (2) Sign each completed task with the session that finished it. (3) Name who owns each task.

THE CATCH, which the user raised: sessions are ephemeral. A long session is cleared or compacted every so many tokens of context, and each /clear starts a new conversation id, so a signature by session id would split one line of work into many names.

WHAT EXISTS TODAY, for the design. Owners are Claude Code processes (pid, start tick, boot; decision [343](../decisions.md#343)), shown as 'profile on pts/N'. A process spans every /clear in its terminal, but an exit and resume starts a new one. The conversation id changes at each /clear and survives a resume (note 360). doneBy (e779786, on branch task-354-step3, not pushed) records the process, not the session id. The task list lives per conversation id, so it starts over at each /clear.

OPEN: what names one line of work across clears and restarts (the process, the chain of handoffs, a name the user gives), and what each session shows as its own (a section in the prime, a filter on next and the list). To design with 354's step 4 (several agents on one board), with 357 (questions as items) and 125 (authorship).
