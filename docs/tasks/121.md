### <a id="231"></a>231. BUILT 2026-09-21, committed as 71f2618 on main (local, not pushed, not released). A lone - in place of the description…

BUILT 2026-09-21, committed as 71f2618 on main (local, not pushed, not released). A lone - in place of the description reads it from stdin, for --task, --note and --edit (main.rs described). The rule is ekko::reads_stdin: exactly one -, and every other token a @board, p:N or d:. So 'fix - now' stays a literal word and stdin is not read. ekko::with_description swaps the - for the text, trimmed and prefixed with a NUL, which argv can never carry. parse_create_options and edit_description take that token verbatim, so a text starting with @x or d: is not read as a board or a date. Inner newlines are kept. Empty stdin gives MISSING_DESC. A terminal on stdin is refused with INVALID_INPUT instead of waiting. KNOWN LIMIT: a pipe that never closes waits forever, as cat does. A Bash tool that runs 'ekko --task -' without &lt; or a heredoc hangs until its timeout (seen once in this session). CHECKS: a test in tests/cli.rs (a_lone_dash_reads_the_description_from_stdin), cargo test 334 green, clippy -D warnings clean. readme has a 'Description from stdin' section plus an example in the help mirror. MCP is untouched: its text never went through a shell.
