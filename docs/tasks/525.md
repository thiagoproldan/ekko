# 525. Cold-return guard: when a prompt arrives after 60+ minutes idle on a context of \~200k or more, stop it once and offer…

*Task · done · medium priority · created 2026-09-24 · [history](../history.md)*

Cold-return guard: when a prompt arrives after 60+ minutes idle on a context of \~200k or more, stop it once and offer /clear from the handoff instead of re-writing the whole context at the cache-write price. Measured (note [518](507.md#518), evals/recall/cold.py): 65 such rewrites in 30 days, 7.5% of the bill, median context 525k, each \~7 points of the 5-hour window (note 444); starting over from a handoff instead would have saved up to \~4.4%. It needs a handoff written while the cache is still warm, which only 4 of the 65 had, so the guard alone is not enough: decide how the handoff gets written before the user leaves. Where it lives -- ctx, which owns the Stop hook and the status line, or ekko -- is the user's call.

Options, any number of them:

- Only what exists: (Recommended) The Stop hook's bands, /handoff and the age in the status line; the guard shows the age and you choose: /clear from the handoff, or send again and pay the rewrite. Re-count in two weeks.
- A delta since the handoff: At the cold return a script reads the transcript since the last handoff -- your prompts, the files and commits touched, the last answer -- and the next session gets it with the prime. Zero tokens to write, a few k to read; facts only, no reasons.

Helps when you are in another session, not when away from the desk.
