(1) One optional field, knowledge: decision|gotcha|procedure, plus supersedes: &lt;uid>, stored on the new note only. create's kind grows to task|note|handoff|decision|gotcha|procedure; the handoff stays its own flag. Superseded is computed (a live note points at it), never written on the old note: the old one is not rewritten, and trashing the new one makes the old one current again.

(2) Both loose and attached. An attached one keeps its meaning after its task is done.

(3) Prime: gotchas and procedures by first line, newest first, at most 5, with a '+N more' line. Decisions only as one count line ('12 decisions: search decision'). Superseded ones never.

(4) supersedes only between notes of the same kind (any of the three), no self-reference or cycle, one successor per note (a linear chain: to replace again, supersede the newest). Refused if the target is trashed. context shows 'superseded by N' and 'supersedes N'.

(5) CLI in 172: --note --kind decision and --supersedes &lt;id>. The marks in the board view and --ui go with 178.

(6) search and --list filters decision, gotcha and procedure, with task [116](116.md) fixed alongside: @due is always the board, bare due always the filter.

(7) Retag 158 and 161-164 only with the user's consent, after the release.
